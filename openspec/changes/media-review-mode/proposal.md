## Why

自动模式批量下载后，用户需要在成百上千个媒体文件里人工筛一遍：留一部分、存疑一部分、删掉一部分。当前工具到"下载完成"就结束了，筛选只能手动在资源管理器里做——逐个看图、剪切、删除，量大时不可操作。前端已具备网格/灯箱组件与本地服务能力（`/media-proxy` 思路），补一组本地文件路由 + 一个审查界面即可闭环。

## What Changes

- **新增审查（review）模式**：选择一个 `downloads/profile_{username}/` 文件夹，逐文件过图打标签：
  - **1 = 保留**：文件留在源文件夹（无操作）
  - **2 = 候选**：文件移动到 `downloads/profile_{username}/_candidate/` 子文件夹
  - **3 = 删除**：硬删除（`os.remove`，不可撤销——用户明确选择，不做回收站）
- **纯文件级粒度**：每个文件独立判定，不按帖分组（多图帖可能被拆开，接受该语义）。
- **动作即时生效**：按键即执行移动/删除，不设批量缓冲；界面展示审查进度（已审 X / 共 Y）。
- **后端新增 `/review/*` 路由**（4 个）：
  - `GET /review/folders`：列出可审查的文件夹（含文件数）
  - `GET /review/files?folder=...`：列出顶层媒体文件（文件名/类型/大小/时间），排除 `.` 开头的清单/边车与 `_candidate/` 子目录
  - `GET /review/file/{folder}/{filename}`：本地文件服务（正确 Content-Type，支持视频）
  - `POST /review/action`：`{folder, filename, action}` 执行 keep/candidate/delete
- **路径安全**：folder 与 filename 全部约束在 `DOWNLOAD_ROOT` 内，拒绝 `..`、绝对路径、非法字符（防路径穿越）。
- **前端**：新增「审查」模式——文件夹选择 → 大图单张流式审查（键盘 1/2/3 打标签、←/→ 切换、网格总览跳转）→ 即时生效 + 进度条；复用现有灯箱交互模式。
- **与自动模式的关系**：审查只动文件系统，不改 `.auto_state.json` 清单——已在清单的帖子不会因文件被删/移走而重下；**未进清单的文件**（手动下载遗产）被移入 `_candidate/` 后，未来自动任务会重新下载一份到顶层（文件级去重只看顶层路径，已知边界，接受）。

## Capabilities

### New Capabilities
- `media-review`: 本地媒体审查——文件夹/文件枚举、路径受限的本地文件服务、三档动作（保留/候选/删除）即时执行、纯文件级粒度、进度可观测。

### Modified Capabilities

（无——不改变既有能力的需求；`auto-download` 与 `instagram-collection` 的行为不变，仅在 proposal 记录上述已知交互边界。）

## Impact

- **main.py**：新增 4 条 `/review/*` 路由与路径校验辅助函数；无既有路由改动。
- **frontend/src/App.jsx / App.css**：新增审查模式（模式切换入口、文件夹选择、大图流 + 键盘快捷键 + 网格总览 + 进度）；复用 `proxiedMediaUrl` 之外的本地文件 URL 构造。
- **无新依赖**；不触碰 collector 层（审查是纯后处理，不联网、不占动作名额、不涉风控）。
- **风险**：硬删除不可撤销（用户选定）；误触防护靠按键确认语义（仅 1/2/3 三个键，无复合键误触面）与删除后 UI 即时移除。
